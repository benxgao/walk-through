## The product's home is its own repository; a consumer copies the folder

- `walk-through` holds the folder, the skill, the rules and the first compiled suite. It is the only
  place a rule changes.
- A consumer gets a copy of `walkthrough/` and writes its own `journey.md` there. No submodule, no
  package, no link: the compile reads a folder, and a folder is what a copy is.
- The first journey written here is about **this product**, because the card asked for one scenario
  failing for the right reason and a journey about an unbuilt consumer fails seven times for no
  reason. The consumer's journey is written in the consumer, during the install test.
- `small-talk-agents` keeps its own copy and is the test consumer. It is not a second home: no rule
  there is authoritative, and a change that only exists there is drift.

### Alternatives

- Keep the journey about the consumer product in this repository — a document about something that
  does not exist yet, checked by a suite with nothing to read.
- A git submodule per consumer — moves the drift to a repository boundary instead of removing it, and
  every path becomes a cross-repository reference.
- An npm package with `walkthrough init` — a version number and a build step for four markdown files
  and one skill; the copy is one `cp -r` and the diff is readable.

### Consequences

- A consumer's copy can drift. The install test records the version it copied, and the compile diff
  is the only guard — cheap at one consumer, a real decision at three.
- Fixing a rule here does not fix it in a consumer; someone copies again, deliberately.
- Not in the code: no file states which repository is authoritative. `walkthrough/skill/SKILL.md`
  and this entry are the only places the question is answered, and only this one says why.
